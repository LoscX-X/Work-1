# LabLens 录屏步骤与讲稿

目标成片 **7 分 10 秒左右**，其中 **4:20—6:40 为 2 分 20 秒真实 AI 协作过程**。本届要求为 5—8 分钟、1080p、MP4，AI 过程至少 2 分钟；录完以实际成片重新核对。[赛项要求](https://www.boxuegu.com/matchTrack/detail/?id=10039)

## 一、录前准备

1. 解压最终交付包，双击 `Start-LabLens.cmd`，浏览器打开 `http://127.0.0.1:4173/`。
2. 打开本项目 GitHub、技术 PDF 和原始 Codex 聊天，准备好与开发有关的三轮提示/修复位置。准备终端在项目目录执行 `git log --oneline --reverse`、`npm run check`。
3. 数据文件使用 `public/samples/sensor-calibration.csv`。七步实际配置为 `public/samples/sensor-cleaning-recipe.json`；预先打开所在文件夹，方便导入。
4. 浏览器窗口放大到易读尺寸，关闭无关标签和通知。整个视频只展示本项目及本次比赛材料。
5. 用 OBS 录制桌面，便于在浏览器、Codex、终端和 PDF 之间切换。

## 二、OBS 设置

- 从 [OBS 官方网站](https://obsproject.com/download) 获取软件。首次自动配置选择以录制为主。
- 在“来源”添加“显示器采集”，选择准备展示项目的屏幕；预览中确认浏览器、终端等都能被录到。
- “设置 → 视频”中，基础画布和输出均设为 **1920×1080**，帧率 **30**。按预览调整窗口与缩放，让文字清楚。
- 检查麦克风音量条，先录一小段，播放确认画面和人声正常，再正式录制。
- 录像格式可选 MKV，录完在“文件 → 录像转封装”生成 MP4；也可按当前 OBS 的录制设置直接输出合适的 MP4。最终提交的一定是 MP4。
- 画质以能读清提示词、表格和代码为准。上传大小限制需查看实际提交页，不能假设一个未核实的上限。

设置依据为 [OBS 快速开始](https://obsproject.com/kb/quick-start-guide) 和 [录制/转封装说明](https://obsproject.com/kb/standard-recording-output-guide/)。

## 三、逐段录制

### 0:00—0:25 · 问题与目标

画面：打开 LabLens 首页。

讲稿：

> 我的作品是 LabLens 实验数据体检与可视化工作台，面向本科实验课的表格整理。实验数据常有缺失、格式错误和重复记录，直接画图可能掩盖这些问题。我希望把问题定位、清洗确认、分析和处理依据连成一个可以复现的流程。

### 0:25—1:10 · 原始数据与定位

操作：点击“使用示例”；指出 163 行、6 列和 13 个检查项。点击“4 缺失值”展示具体位置；返回概览或图表，点击明显的 580 mV 异常点，定位源记录 #20。

讲稿：

> 这里使用固定种子生成的合成传感器标定数据。当前检查包含四个缺失值、三个格式错误、三条额外重复记录和三个疑似异常值。点击检查项可以回到源记录。右侧的参考分是受影响单元格比例，不代表数据真实或处理一定正确。

### 1:10—2:40 · 预览、确认与七步清洗

进入“清洗工作流”，每次先“查看影响预览”，核对后“确认执行”。按以下顺序操作：

| 步骤 | 操作和字段 | 预期记录 / 检查项 |
| --- | --- | --- |
| 1 | 清除首尾空白，全部字段 | 163 / 13；修改 2 格 |
| 2 | 移除额外重复记录 | 160 / 10；移除 #162、#163、#164 |
| 3 | 格式错误转为空值，传感器输出_mV | 160 / 10；修改 2 格 |
| 4 | 格式错误转为空值，温度_℃ | 160 / 10；修改 1 格 |
| 5 | 移除缺失记录，全部字段 | 153 / 3；移除 7 条 |
| 6 | 处理疑似异常记录，传感器输出_mV | 151 / 1；移除 #20、#107 |
| 7 | 处理疑似异常记录，温度_℃ | 150 / 0；移除 #141 |

在第 2 步后示范一次撤销和重做，再继续第 3 步。若操作速度较慢，可保留前两步演示，再到“追溯与导出”导入七步配置，展示试运行、指纹核对和确认回放；明确说明后五步由已保存配置重放。

讲稿：

> 每次清洗先列出真实变更，原始数据保留。重复处理只移除额外记录，撤销可以恢复。这个演示里，我根据合成数据已知注入的问题选择排除无效和异常记录，最终保留一百五十条。真实实验中需要结合背景判断，不能为了提高拟合分数随意删点。

### 2:40—3:20 · 分析前后对照

操作：进入“可视化分析”，X 选参考压力_kPa，Y 选传感器输出_mV，分组选实验组。切换一次“原始数据 / 当前结果”。

讲稿：

> 原始数据有一百五十九对有效观测，R² 约为零点五六六；当前结果有一百五十对，斜率约一点八七四五九，截距约八点七四八九一，R² 约零点九九九八二。两组用不同颜色显示，拟合线是所有纳入观测的整体普通最小二乘拟合。统计同时列出没有参与分析的记录数量。

这是本文件、本策略的计算结果，不作其它数据的效果承诺。

### 3:20—4:20 · 导出与复现

操作：进入“追溯与导出”，导出当前 CSV、完整处理记录、清洗配置和 HTML。打开 HTML，展示图表与步骤。点击“使用示例”重新载入原文件，再导入刚导出的配置，展示七步试运行与结果指纹通过，确认回放。

讲稿：

> CSV 保存当前全表，完整处理记录保存逐格变更和移除的源记录。HTML 带有内嵌图表，离开应用也能查看。清洗配置绑定原文件和处理结果指纹。重新导入相同文件后，只有整条操作序列校验通过，才可以一次性应用。

### 4:20—6:40 · 真实 AI 协作过程，保留至少 2 分钟

实际切到 Codex 原始聊天、真实任务提示和对应代码/提交。可以回看本次开发记录，不需要重新伪造一轮开发。若原聊天不易定位，展示 `docs/ai/actual-dialogue-excerpts.md` 时说明它是从本地日志提取的公开消息摘录；任务 Markdown 是 AI 按委托整理并实际使用的提示。

| 时间 | 画面与操作 | 讲解要点 |

可以按以下文字自然讲解：

> 我负责确定主题、功能边界和验收方向，Codex 承担主要代码实现与验证。开发分为导入体检、可撤销清洗、分析与回放三条核心迭代链。每一轮先记录具体任务和验收条件，再把真实结果写回记录，并保留对应 Git 提交。
>
> 第一轮强调原始值和源记录，第二轮强调不可变操作与预览确认，第三轮强调统计口径和可复现。发现问题后修改实现并重新验证。这里展示的是实际聊天、阶段任务、代码差异和运行结果；任务提示由 AI 根据我的委托整理，没有把它们写成我逐条输入的对话。

### 6:40—7:10 · 运行与边界

画面：README 启动步骤、技术 PDF 和最终项目。

讲稿：

> 项目采用 React、TypeScript 和 Vite，解析与图表库随包提供。源码可以安装依赖后构建，预构建包只需 Node 启动。数据在浏览器本地计算。当前支持 CSV、TSV 和 XLSX，工作区刷新后需要重新导入原文件与配置。技术文档、验证记录和完整开发历史在仓库中提供。
