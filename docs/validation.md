## 独立检查实际导出文件

保存的两步填充场景位于 `docs/evidence/browser/`，校验命令：

```powershell
python tools/verify_export_evidence.py
```

该脚本仅用 Python 标准库读取实际文件，未使用前端内部状态：

- 核对原文件 SHA-256：`660a7b924e3ad2c5d60ea7fb8ce3c76a60779a1c2beb05569e277554e048c483`。
- 从原始文件按 JSON 中的逐格变更和移除记录重建结果，与 CSV 的 160 条记录逐项相等。
- 重新计算排除填充值后的 156 对观测，得到斜率 `1.789556189829693`、截距 `15.338367748465544`、R² `0.555055689559629`，与导出 JSON 一致。
- 核对 HTML 中完整记录与 JSON 的来源、字段、前后计数、参数、来源标记相等；仅各自生成时间不同。
- 报告内嵌 PNG 为 1800 × 900；单独下载 PNG 为 1646 × 900，均为有效 PNG 文件。HTML 不依赖外部脚本或图像链接。

结果保存在 `docs/evidence/browser/verification.json`。此脚本验证保存的特定场景，不是自动浏览器测试框架。

## 已知边界

- 只支持 CSV、TSV 和 XLSX；不读取旧版 XLS，不运行 Excel 公式，无缓存公式结果需要先在 Excel 中计算并保存。
- Excel 仅对编号类字段的简单全零格式保留显示前导零；不声称实现完整 Excel 数字格式渲染。
- CSV 的空白记录由解析器略过；源记录编号是包含表头的记录位置，不等于包含多行引号文本时的物理行号。
- 类型推断是建议，可能误判；可手动确认类型。IQR 是提示规则，异常点需要实验背景确认；质量参考分也不是实验真实性证明。
- 当前为浏览器内存工作区，刷新后需重新导入原文件和保存的配置。没有账号、云端存储或多人协作。
- 未完成多浏览器矩阵、所有移动设备、超大文件压力和全部编码/Excel 格式组合的验证。早期窄视图发现的横向布局问题已调整 CSS；后续以实际设备验证为准，不宣称移动端全覆盖。
- 自动化环境曾在下载等待、文件路径转义和视口覆盖上遇到工具问题；最终证据以实际保存文件和截图为准，未将工具尝试次数当成产品功能测试通过次数。
